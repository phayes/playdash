0. Architecture:
----------------

1. **Download workers and requests have no owned lifecycle.** (L)
   - Each blocking `SegmentStream` spawns a detached GET thread, and eager HEAD a second one (segment/stream.rs:224, 297). No `JoinHandle` is kept; `Drop` only sets `cancelled`, which the worker checks between requests. `Transport` has no cancellation.
   - `SegmentCache::get` holds the segment's `blocking_fetch` mutex across the network call (segment/cache.rs:110), so one hung GET blocks every stream waiting for that segment, and dropping the stream does not free it.
   - The async stream captures `Handle::current()` at open and spawns every task there; if that runtime shuts down, the fetch task dies without a terminal stream error.
   - Streams scale as OS threads, not as requests.
   - ExoPlayer's `Loader` owns its load tasks and cancels them; dash.js's `HTTPLoader` aborts requests.
   - Refactor: a download coordinator scoped to the presentation, with owned workers, explicit shutdown, cancellable requests, and in-flight state in place of a mutex held across I/O. Async: an injected spawner or an explicit driver, with supervised tasks.

2. **There is no presentation or session object.** (L to XL)
   - `DashManifest` is a cloneable value that shares a mutable `Arc<Live>`:
     - `with_base_url` changes the shared `Live`, so it affects every clone and every stream already open.
     - For a live manifest, `representations()`, `mime_type()`, `highest_bandwidth()` and `protection_scheme()` read the MPD as parsed, while `segments()` reads the refreshed one.
     - `segments(id)` registers the representation for refreshes as a side effect (live.rs:265-290).
   - Refresh admission is split by I/O flavour: `Live` has separate blocking and async refresh locks (live.rs:174-179), so blocking and async streams from one manifest can both fetch and install a refresh.
   - `Live::segments` and `Live::install` build and align indexes while holding the presentation-wide state mutex, so a large timeline stalls opening and index adoption for every stream.
   - The clock is split: streams use `Live`'s clock, while `Segments::available()`, `media()` and `segment_at()` use `SystemTime::now()`. They will disagree once `UTCTiming` wraps the clock.
   - Options are spread out and arrive late:
     - Retention and live delay reach a stream only through `MediaStreamBuilder`; `segment_stream_retained` is crate-private.
     - `segment_stream_at` drops retention for live; `DashSource` takes no retention, so a static `DashSource` keeps everything.
     - `SegmentStream::with_retention` / `with_behind_window` apply after the GET worker has started (examples/list_tracks.rs works around this with `Retention { 0, 0 }`).
     - `MediaStreamBuilder::open_at` is `open()` then `seek_time()`, so a static stream starts downloading at segment 0.
     - Inspecting tracks or the codec means opening a stream that downloads media.
   - Controls and status live on the reader: `is_live`, `available`, `live_edge` and `buffer` are forwarded through `SegmentStream`, `PacketStream`, `MediaStream`, the async copies and `DashSource`. A reader moved into a thread can no longer be asked, and each rebuilt stream gives a new `BufferHandle`, so `on_change` callbacks must be registered again. rodio works around this with a private weak `StreamHandle` and `BufferFeed`.
   - Nothing owns a group of streams: examples/video_player.rs implements its own audio/video seek, combined buffer status and shutdown.
   - Transport ownership differs: async keeps a `Client` on `nonblocking::DashManifest`, but `nonblocking::SegmentCache::default()` makes a new one, silently ignoring `with_client`. Blocking default caches each make their own ureq agent, so nothing is pooled unless the caller passes caches around.
   - ExoPlayer's `DashMediaSource` owns the refresh loop and publishes immutable `DashManifest` snapshots; `Player` (control and listeners) is separate from `SampleStream` (data).
   - Refactor:
     - An immutable manifest snapshot plus a session handle that owns the clock, refresh admission, a default cache, prepare (init only: tracks, codec) and then open, and cloneable observation handles. A durable buffer subscription lives on the handle.
     - Keep the settled "run on demand by whichever stream's worker needs it": the coordinator admits one refresh, and the stream that needs it does the fetch through its own transport.
     - Make the refresh logic sans-IO (`due(now)`, `install(fetched, now)`), as `Schedule` already is, and build indexes outside the state lock, committing if the generation still matches.
     - Keep `SegmentStream::new*(Segments)` and `PacketStream::into_media_stream*` as the lower-level composition paths.

3. **No single parsed model of an init segment, a track or a codec.**
   - Parse once (M):
     - A keyed `MediaStreamBuilder::track(kind).open()` parses one `moov` four times: `cenc::clear_sample_entries`, `cenc::protection` (in `Store::media_role`), `track::tracks` and `Demuxer::new`.
     - There are two types named `Track` (`mp4::init::Track`, `mp4::track::Track`).
     - The media kind is encoded as `hdlr` bytes, `ContentKind`, `Demuxer.audio` and the public `Track.kind`.
     - Refactor: one `Arc<InitSegment>` built per init body (tracks, sample entries, protection), and the codec resolved only for the selected track. ExoPlayer's `FragmentedMp4Extractor` turns `moov` into `Track`s once.

4. **Decryption happens inside the shared cache, keyed by URL.** (L)

2. Container wrapping for raw-demuxer decoders
----------------------------------------------

Goal: every codec's `MediaStream` output can be piped to a decoder that reads a
byte stream, such as the `ffmpeg` CLI through ffmpeg-sidecar, without the
caller writing a container muxer.

What is missing today

- Opus has no raw byte-stream form: `ffmpeg` and other raw demuxers read it
  only in Ogg, with the `OpusHead` and an `OpusTags` header first and the
  packets paginated, each page with a granule position and CRC.
- VP9 has none either: it needs IVF, a 32-byte file header (width, height,
  timebase) and a 12-byte frame header before each frame.
- AAC has `DecoderFormat::AacAdts`, but only when asked for by format; neither
  `DecoderStyle` gives it.
- tests/decoder.rs already wraps all three for its ffmpeg checks (`feed`, with
  Ogg pages and CRC, IVF, and ADTS); none of it is public.

Plan

- Promote the Ogg Opus and IVF wrapping from tests/decoder.rs, either as new
  `DecoderFormat`s (e.g. `OpusOgg`, `Vp9Ivf`) whose initialization is the
  container header and whose packets carry their page or frame header, or as
  separate helpers that wrap a `MediaStream`'s initialization and packets.
- Update `DecoderStyle`'s decoder table: the ffmpeg-sidecar Opus and VP9 rows
  point at the new format.

Open questions
- New `DecoderFormat`s, or helpers outside the format enum? Formats keep "one
  packet in, one packet out" and work with `MediaStreamBuilder::format`, but
  they are containers, not decoder input.
- Ogg granule positions and IVF frame counts after a seek: restart the
  container, or keep counting?
- IVF's header has a frame count, unknown while streaming: write 0, as ffmpeg
  accepts?


3. Adaptive bitrate switching
-----------------------------

Goal: callers can switch between a stream's representations as network
conditions change, choosing when and to what themselves. playdash reports
when downloads fall behind or recover, and gives the pieces for a clean
handover at a segment boundary; it ships no ABR algorithm of its own.

Decisions (settled)

- The signal is buffer events, not throughput: callers subscribe to
  underruns and to low/high watermarks on buffered-ahead time. No transfer
  hook on `SegmentCache` and no throughput estimator in the library.
- A switch is two streams composed by the caller (the video_player example's
  seek pattern): open the new representation on the same `SegmentCache` at
  the old stream's next segment boundary, drain the old one to it, hand over.
  The new stream brings its own `initialization()` and `timescale()`, so a
  change of codec config, resolution or timescale needs nothing special.
- An underrun is the reader needing a segment that has not arrived. It says
  the download fell behind reading, not that playback stalled: playdash
  cannot see the player's own buffer.
- Waiting at the live edge for a segment that is not published yet reports as
  an underrun with cause `LiveEdge`: not a network problem, but close enough
  to fit the model.
- Live latency is reported as a `Duration`, not a packet count: packets in
  undownloaded or unpublished segments are unknown, audio and video packets
  differ in length, and the thresholds it is compared against
  (`suggestedPresentationDelay`, the start delay, the watermarks) are times.

Plan

Events on `BufferHandle`, next to `on_change` (sync callbacks, so the
blocking and async APIs share them)
- `BufferHandle::on_underrun(callback(&Underrun))`. `Underrun` carries the
  representation id, the read position (presentation time), the segment
  number waited on, a cause and a phase:
      enum UnderrunPhase {
          Started,
          Ended { waited: Duration, bytes: u64, transfer: Duration },
      }
      enum UnderrunCause {
          Startup,                              // first segment after open
          Seek,                                 // first segment after a seek
          Playback,                             // reader caught up with the download
          LiveEdge { available_at: SystemTime },
      }
  `Ended` carries the arriving segment's size and transfer time, so callers
  get a rough throughput without an estimator. ABR rules ignore `Startup`
  and `Seek`. `LiveEdge::available_at` tells a normal edge wait from a
  stalled publisher (`available_at` past and still nothing).
- Watermarks: `MediaStreamBuilder::watermarks(low, high)` (blocking and
  async), with `SegmentStream::with_watermarks` underneath. `Low` fires when
  the media buffered ahead of the read position drops below `low`, `High`
  once it climbs back above `high`; the gap between them keeps the events
  from flapping. Each event carries the buffered-ahead time and
  `behind_live_edge`.
- `BufferStatus::behind_live_edge: Option<Duration>`, `None` while static.

Two-stream switch helpers
- `MediaStream::next_boundary()`: the next segment boundary past what has been
  read, where a switch can take place.
- `MediaStream::end_at(time)`: stop downloading and reading at `time`, so the
  old stream does not fetch old-quality segments while the new one competes
  for bandwidth. Segments already buffered ahead stay readable by default.
- `set_retention` at runtime, so callers can shrink or widen the ahead window.
  The default `Retention { ahead: None }` downloads through the end, which
  defeats ABR; the ABR docs and the example set a bounded `ahead`.
- `DashManifest::alternatives(id)`: representations interchangeable with this
  one (same adaptation set), by bandwidth. Expose `@segmentAlignment` /
  `@subsegmentAlignment` (the vendored crate parses `@segmentAlignment`), so
  callers know whether boundaries line up across representations.
- `DecoderInitialization::same_config(&other)`: whether a decoder can keep
  running across the switch (e.g. Annex B with in-band SPS) or needs a reset.

Example and tests
- `examples/abr.rs`, with a `ThrottledTransport` that drops bandwidth partway
  through so a switch happens on every run: step down on `Low` or a
  `Playback` underrun, step up after `High` has held for a while, and log
  each decision.
- Integration test on the same throttled transport: no gap and no overlap in
  the timeline at the switch boundary.

Builds on the live-stream work (done)
- `LiveEdge` uses the index's "when the next segment becomes available"
  query (`MediaIndex::available_at`) and the readers' waiting at the edge.
  `behind_live_edge` uses the live edge (`MediaIndex::live_edge`).
  `next_boundary` while live respects availability, as reads at the edge do.
  Boundaries are presentation times, so per-representation segment numbers
  need not line up across a switch.

Out of scope for this entry (note, don't solve)
- Abandoning an in-flight download that is too slow (dash.js's
  `AbandonRequestsRule`); needs cancellation in `Transport`.
- ABR on the byte-stream path (`SegmentStream`, rodio `DashSource`): symphonia
  cannot take a second `moov` mid-stream. Possible only when every init is
  identical (`@bitstreamSwitching`).
- Choosing the starting bitrate (e.g. from the network type).
- A library-side switch, `MediaStream::switch_to(id)` at the next boundary: it
  needs an "initialization changed" signal in the packet iterator and handles
  `pts` units changing with the timescale. Revisit if composing two streams
  proves painful; it would reuse `Schedule::replace_index` and
  `MediaIndex::aligned_to`'s alignment by start time.
- Switching across adaptation sets
  (`urn:mpeg:dash:adaptation-set-switching:2016`).

Open questions
- `end_at` on an up-switch: keep the old-quality segments already buffered
  ahead (the default above), or offer to drop them for a faster switch?
- Watermark thresholds per stream only, or also a combined audio+video view,
  as `BufferStatus::buffered_until_all` gives for buffer status?


Additional TODOs:

These are ranked by how much they matter. These are candidates for follow-up work where a firm decision hasn't been taken.

1. **Representations are found by ID across all periods.**
   - dash.js identifies a representation by Period → AdaptationSet → Representation: one `Stream` per period, and `path [p,a,r]` on each representation.
   - playdash finds one by ID across the whole MPD, ignoring case, with a fallback to the token before the first comma. The first match wins (mod.rs:458).
   - So when periods repeat IDs, every period after the first is unreachable. That accounts for 24 of the 30 conformance `fail/` entries.
   - It also explains a latent bug nothing ever hit: a later `Period` with no `@start` is treated as starting at 0 (mod.rs:240, mod.rs:197).

2. **SegmentBase works by rewriting the parsed MPD.**
   - `apply_index` writes a synthetic `SegmentList`/`SegmentTimeline` into the vendored MPD structs (segment_base.rs:75-93). Load failures are kept in a side map, `segment_index_errors`.
   - dash.js keeps `SEGMENT_BASE` as its own segment-info type, with `SegmentBaseLoader` and `SegmentBaseGetter`; the parsed manifest is never altered.
   - Consequences:
     - `DashManifest::new` can return representations that cannot be streamed until I/O has run.
     - The manifest no longer matches the document it came from.
     - Errors surface late, through the side map.

3. **Inheritance is worked out again on every query.**
   - Three ad-hoc chain types do it: `TemplateChain`, `ListChain` and `BaseChain`.
   - Two more functions repeat the "which addressing applies" decision: `needs_segment_index` and `uses_segment_list` (mod.rs:131-166).
   - dash.js resolves inheritance once, at parse time (objectiron), and computes `segmentInfoType` once per representation.
   - A single resolved representation, built once, would replace all of this.

4. **Naming: `manifest::segments` (timing arithmetic) and `segment::Segments` (the public list) are different things.** Segment timing and URLs are no longer built as separate lists: templates fill each URL from the segment's number and time, and `ListChain::segments` pairs each `SegmentURL` with its timing as it builds the list.

5. **No retries, failover or error types.**
   - The first failed GET ends the stream.
   - The GET worker converts the error to a string (segment/stream.rs:552), so callers get `Error::Io` instead of the original type.
   - A single failed HEAD turns size probing off for good.
   - Only the first `BaseURL` at each level is used (mod.rs:267).
   - dash.js has retry counts and intervals per request type (media 3×1000 ms, MPD 3×500 ms), timeouts per type, a BaseURL blacklist, and failover with DVB priority and weight.

6. **The blocking and async code are near-copies of each other.**
   - `segment/stream.rs` and `nonblocking/segment/stream.rs` differ in about 3,000 lines.
   - Cache, transport, the packet-stream seek loop and the `MediaStream` builder are also copied.
   - `Schedule` and `Store` contain no I/O. The segment streams' shared steps now live on `Schedule` (GET and HEAD worker steps, `size_step` for `ensure_sizes`, time and byte seek begin/land, `reported_end`); what is left in each stream is its waiting, its I/O, and the read loops around them. Still copied: the packet-stream seek loop in `packet/stream.rs` and `nonblocking/packet.rs`, the caches, transports and `MediaStream` builders. dash.js has a single code path, so there is no direct comparison.

7. **The first manifest fetch has no caller-chosen `Transport`.**
   - Since live-stream support, `new_from_url` and live refreshes fetch through `Transport::fetch_manifest` (one ureq agent for the MPD and its indexes; the async version's `Client`), and refreshes use the stream's own transport.
   - There is still no `new_from_url_with_transport`, so custom transports and test fixtures cannot intercept the first load.
   - dash.js loads the MPD, init, index and media segments through one HTTPLoader.

8. **Code written for one consumer's quirks sits in the core segment layer.**
   - The symphonia-compat length padding is in `segment/mod.rs:142-145`, `Segments::estimate_len`, `Schedule::reported_end_len` and `SegmentStream::set_symphonia_compat`.
   - rodio.rs never calls any of it.
   - It belongs in the rodio adapter, or can be removed.

9. **Protection info in the MPD is ignored, and decryption is audio-only.**
   - `cenc:default_KID` and `pssh` are parsed by the vendored crate but never read. Keys come only from `tenc` in the init segment.
   - `protected_entries` skips any track whose handler is not `soun` (cenc.rs:272). Encrypted video therefore fails later with "samples are encrypted", not with a clear "unsupported" error.

10. **Every `SegmentList` segment is built up front.** Templates now compute segments on demand, but `SegmentList` and `SegmentBase` build a `Vec` of `MediaSegment`s, one per `SegmentURL`. That matches what the MPD lists, so it only matters for very long lists.

11. **Live follow-ups left over from the live-stream work.**
    - A store entry stays when its segment is trimmed while a GET of it is in flight.
    - A 404 for a segment the clock still counts as available ends the stream (needs retries, Additional TODOs 5, and `UTCTiming`).
    - Retrying a failed refresh: today it fails the stream, as a failed GET does (Additional TODOs 5).
    - `UTCTiming` clock sync: a server offset around `Live`'s `Clock`.
    - Live `SegmentList` / `SegmentBase`: today they fail with `DashManifestUnsupportedLive`.
    - Multi-period live, where a new period can bring a new init segment. `SegmentNumber` should leave room for a period index; the byte stream would need to re-emit an init at the boundary, which most fMP4 demuxers only accept by starting again.
    - Low-latency DASH (chunked transfer, `availabilityTimeComplete=false`). It ties into the TODO in schedule.rs about publishing a `moof` before its `mdat` arrives. A low-latency media segment arrives as several CMAF chunks, each a `moof`+`mdat` movie fragment, so this is where "fragment" (or "chunk") names a part of a segment.
    - Refreshes signalled in-band by `emsg` (ExoPlayer's `PlayerEmsgHandler`), and MPD patches.



Bugs to fix later:

Found in the same review; each needs one of the refactors above, or a design decision, to fix properly.

1. **A hung GET or HEAD blocks every stream that needs that segment, and dropping the stream does not stop it.** The per-segment fetch mutex is held across the request. Refactor 1.
2. **An async stream whose runtime shuts down can leave reads pending forever.** The fetch task dies without a terminal error (reported by the reviewer, not reproduced). Refactor 1.
3. **Blocking and async refreshes of one live presentation are not serialized,** so both can fetch and install the same generation and race the stale-retry state. Refactor 2.
4. **A live `DashManifest` answers representation queries from the original MPD,** and `with_base_url` on one clone changes the live state of every clone and open stream. Refactor 2.
5. **`nonblocking::SegmentCache::default()` ignores `nonblocking::DashManifest::with_client`.** `segment_stream_with_cache(id, Arc::default())` silently uses a new `Client`. Removing `Default` is breaking. Refactor 2.
6. **A panicking `on_change` callback ends the download worker and leaves readers waiting with no error;** a slow one stalls downloads. Refactor 6.
7. **The same segment URL opened under two different protection contexts decrypts with whichever role was set first.** The second `OnceLock::set` is ignored. Refactor 4.
8. **Response bodies are read without a size limit.** Both transports read the whole body (`read_to_end`, `Response::bytes()`), and a server that ignores `Range` sends the whole resource before the range is sliced and its length checked. Needs configurable limits for manifest, init, index and media bodies in both transports.
